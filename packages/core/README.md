# @nibblecue/core

Domain types, the module registry, the plan matrix and the versioned guidance data. Pure
TypeScript — **no React, no React Native, no Supabase client, nothing from `apps/`** — so the
schedule engine and the stash ledger can be unit-tested in node and reused by the admin
console and the worker (`CLAUDE.md §5`). An ESLint rule and `src/boundaries.test.ts` both
enforce it.

| Path | What | Origin |
|---|---|---|
| `src/domain/domain-types.ts` | shared types + Zod schemas, canonical units, the outbox shape | copied from `assets/domain-types.ts` at WP0; the assets copy was retired on 2026-09-27 (`docs/REMAINING.md`, the handoff mirrors) |
| `src/modules/module-registry.ts` | THE module registry — every trackable module declared once | copied from `assets/module-registry.ts` at WP0; the assets copy was retired on 2026-09-27 (`docs/REMAINING.md`, the handoff mirrors) |
| `src/plan/entitlements.ts` | THE plan matrix: `can(key, tier)`, `limitFor(key, tier)`, `GATES` | `assets/entitlements.ts`, verbatim |
| `src/plan/entitlements.test.ts` | parity with `pricing.config.json`, the bill of rights, "Free is a working app" | `assets/entitlements.test.ts`, verbatim |
| `src/plan/pricing.config.json` | the same matrix plus the target price points for the store dashboards | `assets/pricing.config.json`, verbatim — regenerated by `tools/gen-pricing.mjs` |
| `src/guidance/*.json` | milk-storage and immunisation guidance, versioned data with source and date | `assets/*-guidance.*.json`, verbatim — never edited by code |

Later work packages add `src/schedule/` (WP7), `src/stash/` (WP6), `src/widget/` (WP9) and
the derivations `todayTotals`, `nextEvent`, `bestUseAt` (`docs/ARCHITECTURE.md §6`).

```bash
pnpm --filter @nibblecue/core test        # vitest
pnpm --filter @nibblecue/core typecheck   # tsc --noEmit, strict
pnpm test:entitlements                    # from the root: the plan-matrix gate
pnpm check:pricing                        # pricing.config.json is in sync with the matrix
```

Zod is pinned to 3.x on purpose: the schemas use `z.record(z.unknown())` and the lenient
`.uuid()` that the seed's fixture ids rely on; Zod 4 rejects both. Moving to Zod 4 is a
deliberate change with its own tests, not a version bump.
